# NBD Block Devices

ZeroFS exposes files under `.nbd/` as Network Block Device exports. A Linux NBD client can attach an export as `/dev/nbd*`, where it can hold a filesystem or serve as a ZFS vdev. {{ className: 'lead' }}

<Warning>
  The NBD server does not authenticate clients or encrypt traffic. Keep it on
  loopback, a Unix socket, or a network with access controls.
</Warning>

## Configure the Server

Enable a TCP listener, a Unix socket, or both:

```toml
[servers.nbd]
addresses = ["127.0.0.1:10809"]
unix_socket = "/tmp/zerofs-nbd.sock"
```

Omit `addresses` when only local Unix-socket access is needed. Start the server after editing the configuration:

```bash
zerofs run --config zerofs.toml
```

## Create an Export

For a striped export, point the ZeroFS CLI at a writable 9P endpoint. This
creates the `.nbd` layout through ZeroFS itself; no temporary host mount is
needed:

```bash
zerofs nbd provision-striped \
  unix:/tmp/zerofs.9p.sock \
  database \
  --size 64GiB
```

The defaults are four equal sparse lane files and a 256 KiB stripe. A 1 MiB
Linux NBD request therefore spans all four lanes instead of serializing on one
backing inode. Both values are configurable when the export is first created:

```bash
zerofs nbd provision-striped \
  tcp://127.0.0.1:5564 \
  database \
  --size 64GiB \
  --lanes 8 \
  --stripe-size 2MiB
```

The logical size must be divisible by `lanes × stripe-size`. ZeroFS accepts
2-32 lanes and power-of-two stripe sizes from 4 KiB through 64 MiB. Repeating
the command with the exact same geometry is safe: it verifies the manifest and
every lane, flushes the export, and reports that it is already provisioned.
Conflicting existing files, directories, or geometry are never replaced.

Provisioning builds the marker, sparse lanes, and NBD manifest in a unique
hidden sibling directory. It flushes that complete staging layout before one
atomic no-replace rename publishes the final export name. Each attempt owns its
staging directory exclusively; interrupted staging directories are left
untouched for manual inspection and are never resumed automatically. An
incomplete directory already using the final export name is rejected without
modification and must be inspected and moved aside before retrying.

<Note>
  `provision-striped` only creates and flushes the export. It does not format a
  filesystem, attach `/dev/nbd*`, or change any existing block device.
</Note>

For a single-file export, mount ZeroFS through [9P](/9p-access) or
[NFS](/nfs-access), then create a sparse file in `.nbd`:

```bash
mkdir -p /mnt/zerofs/.nbd
truncate -s 20G /mnt/zerofs/.nbd/database
ls -lh /mnt/zerofs/.nbd/database
```

The filename or striped-directory name is the NBD export name. New exports are
available without restarting ZeroFS.

## Connect from Linux

Install `nbd-client`, load the kernel module, and connect the export:

```bash
sudo modprobe nbd
sudo nbd-client 127.0.0.1 10809 /dev/nbd0 -N database
sudo nbd-client -check /dev/nbd0
lsblk /dev/nbd0
```

For a Unix socket:

```bash
sudo nbd-client -unix /tmp/zerofs-nbd.sock /dev/nbd0 -N database
```

Common `nbd-client` options have workload-dependent trade-offs:

| Option | Effect |
| --- | --- |
| `-N <name>` | Required; selects the named file from `.nbd/`. |
| `-unix <path>` | Connects through a local Unix socket instead of TCP. |
| `-persist` | Reconnects after a dropped connection. Use it only when reconnect behavior is appropriate for the filesystem or volume manager above NBD. |
| `-timeout <seconds>` | Sets the client I/O timeout. It must cover expected object-store and network stalls. |
| `-connections <count>` | Opens multiple connections to the same export. Measure the workload before increasing it. |
| `-readonly` | Attaches the export read-only. |
| `-block-size <size>` | Requests a block size supported by the client and server. |

ZeroFS advertises multi-connection support. All connections share one filesystem instance and flush path, so a flush on any connection covers completed writes from every connection.

After upgrading a server that no longer advertises a capability, reconnecting
the same Linux NBD device may leave its old queue limits in place. Before
mounting, verify the configured device reports zero for `WRITE_ZEROES`:

```bash
cat /sys/block/nbd0/queue/write_zeroes_max_bytes
```

Older kernels may expose the equivalent limit as
`max_write_zeroes_sectors`; require whichever attribute exists to report zero.

<Warning>
  If the result is nonzero, do not mount it: filesystems such as XFS may issue
  an operation the new server did not advertise. For a one-time reset, first
  unmount and disconnect every NBD device, then prove every
  `/sys/block/nbd*/size` is zero and no `/sys/block/nbd*/pid` identifies a
  client. Only after that proof is it safe to run `sudo modprobe -r nbd`
  followed by `sudo modprobe nbd` and reconnect. If another NBD device must
  remain attached, do not unload the module. Choose a never-used `/dev/nbdN`
  instead, and update the client service, mount unit, and any
  `ZEROFS_PILOT_NBD_DEVICE` setting to that same device.
</Warning>

## Put a Filesystem on the Device

Formatting destroys any existing contents of the export. For a new device:

```bash
sudo mkfs.ext4 /dev/nbd0
sudo mkdir -p /mnt/database
sudo mount /dev/nbd0 /mnt/database
```

Other Linux filesystems and volume managers can use the device if their block-size, flush, and discard behavior is compatible with NBD.

## Durability Commands

The NBD handshake advertises `NBD_FLAG_SEND_FLUSH`, `NBD_FLAG_SEND_FUA`, and `NBD_FLAG_CAN_MULTI_CONN`:

- **FLUSH** waits for ZeroFS's configured client-flush barrier. Concurrent FLUSH and FUA requests can share one filesystem flush.
- **FUA** on WRITE or TRIM waits for the same configured barrier before replying.
- **CACHE** is accepted as a no-op.
- **Structured replies** are not negotiated; clients use simple replies.

With the default `sync_writes = false`, ordinary writes may remain buffered until the next flush. Without persistent writeback, FLUSH and FUA wait for the backing-store flush. With persistent writeback enabled, they wait for the local-journal durability barrier; remote publication may still be pending. The explicit `[filesystem] ignore_fsync = true` setting makes the client-flush path a no-op. See [Durability and consistency](/durability) for the complete persistence model.

## Discard and Zeroing

ZeroFS accepts TRIM requests from filesystems and ZFS:

```bash
sudo fstrim /mnt/database

# For a ZFS pool
sudo zpool set autotrim=on mypool
sudo zpool trim mypool
```

TRIM deletes extent pointers for fully covered extents and debits the affected segments' live-byte counters. Segment garbage collection later deletes empty segments or repacks fragmented ones; object-store usage does not necessarily decrease immediately. See [Garbage collection](/garbage-collection).

ZeroFS does not advertise `WRITE_ZEROES` or fast-zero support. An unexpected
`WRITE_ZEROES` request receives `EINVAL`; use TRIM when the caller only needs to
discard data, or a normal WRITE when the device must contain explicit zero
bytes.

## Resize or Remove an Export

A client keeps the size negotiated at connection time. Disconnect before changing the file size, then reconnect:

```bash
sudo umount /mnt/database
sudo nbd-client -d /dev/nbd0

# Grow the export. Shrinking discards data beyond the new end.
truncate -s 40G /mnt/zerofs/.nbd/database

sudo nbd-client 127.0.0.1 10809 /dev/nbd0 -N database
```

To remove an export, disconnect every client before deleting its file:

```bash
sudo nbd-client -d /dev/nbd0
rm /mnt/zerofs/.nbd/database
```

## Diagnose a Connection

```bash
# Confirm that the kernel module is loaded
lsmod | grep '^nbd'

# List exports visible through TCP
nbd-client -list 127.0.0.1

# Keep the client in the foreground to see connection errors
sudo nbd-client 127.0.0.1 10809 /dev/nbd0 -N database -nofork

# Inspect kernel and block-device state
dmesg | tail -50
cat /sys/block/nbd0/stat
```

For persistent attachment, configure the service manager to start the NBD client after both the network and ZeroFS endpoint are ready, and to unmount the filesystem before disconnecting the device.
